# Architecture

## Continuous visual path

1. `ContinuousScanner` starts the requested camera after a user action. It initializes a persistent `VisionClient` worker and loads the selected game's installed reference shards from IndexedDB. No recognition request uploads a frame.
2. `vision/learned-engine.ts` combines OpenCV contours and pinned Fastweb corner proposals, rectifies perspective, extracts local hashes and pinned XFeat descriptors, shortlists eight references, and checks every rival with exact mutual-nearest matching and RANSAC. A persistent bounded ONNX MatMul accelerates descriptor multiplication; per-reference matching and geometric gates remain unchanged. `vision/engine.ts` retains the ORB compatibility path. Unknown references and insufficient/ambiguous geometry never become eligible solely because they are the nearest candidate.
3. `scan-session.ts` uses global one-to-one spatial/identity track assignment, rejects out-of-order frame replies, and creates one event ID per physical presentation. Quick mode requires one unchanged strong geometric identity result and a current ROI-continuity proof; Strict requires three fresh eligible identity observations spanning 250 ms plus the same proof. Gray capture samples are never converted into new identity observations. Counted identical identities are conservatively reused within an epoch, preserving the maximum simultaneously seen copies rather than recounting camera pans. Camera sessions disable detector-empty rearming: missing proposals, blur and unknown fronts do not establish exit. Stream mode offers explicit **Next copy** for one visible settled identity without clearing other identities; binder mode offers **New page** for the whole layout. Different identities continue to save automatically.
4. `scan-inventory.ts` creates an idempotent event row with unknown condition/finish and identity-only verification. App integration validates and synchronously writes storage before acknowledging a durable success. Undo targets the exact scan event. The selected image reference is not proof of exact physical printing, finish or authenticity.
5. `printing-session.ts` schedules one nonblocking local footer read after a durable identity save. Native-detail crops and two distinct captures are required; `printing-catalog.ts` supplies complete scoped candidates with a fail-closed cache. Literal catalog identifiers are stored separately, without changing identity-only valuation or physical condition/finish. Cancellation and event guards prevent late refinements.
6. `pricing.ts` retrieves provider quotes independently after an accepted match. A cached result may display immediately while refreshing. Variant, currency, catalog-vs-printing scope and source timestamps remain explicit. Identity-only entries are excluded from valuation totals.

The browser worker accepts one in-flight operation. A separate bounded sampler keeps compact real gray captures while identity inference runs, with at most one full-resolution input and one recycled spare. A current-view commit requires the newest completed capture and is withheld while a newer source readback is in flight. Advancing native presented-frame metadata establishes source freshness independently of readback timestamps; source identity/usability and native presentation age are rechecked at commit. Fixed area/binomial gray preprocessing prevents nearest-neighbor sampling alias from masquerading as card motion, without changing the continuity or identity rejection thresholds. Ordered gray replay has fixed sample, byte, gap and duration limits; overflow invalidates evidence rather than dropping intermediate samples. Pause, hidden tabs, stop, navigation, game changes and unmount prevent late saves. Video and overlays share the same full-frame geometry without CSS cover-cropping or mirroring.

## Reference data

`learned-packs.ts` validates checksummed binary feature records plus metadata, transactionally stages imports, marks only complete packs ready, and reads descriptor blocks lazily with an eight-reference LRU. The initial index contains no descriptor arrays. Interrupted/corrupt packs cannot be loaded.

`database-install.ts` coordinates an explicit one-click download through the included local server. `server/reference-installer.ts` accepts only the pinned public Pokémon release, verifies size/SHA-256, resumes a controlled partial cache and serves bounded byte ranges. `learned-archive.ts` parses a bounded ZIP directory and inflates one member at a time with CRC validation, then uses the same transactional learned importer and manifest/shard checks. Official installation pins the manifest before database writes. A single downloaded ZIP is the static-host fallback; raw manifest/shard selection is advanced setup. No frames or collections are sent to the installer.

`reference-packs.ts` validates compatibility data-only feature packs, bounds per-shard size/counts, stores checksummed packs in IndexedDB and verifies same-origin prebuilt downloads. Installed and loaded coverage are distinct. No full catalog is bundled, and a fresh source install has zero local visual references.

`scripts/build-index.mjs` builds resumable descriptor shards from provider catalog metadata and locally cached source images using the same preprocessing as the browser. Raw artwork is never committed. Generated-feature redistribution rights are separate from the application's MIT source license. See [reference packs](reference-packs.md) and [recognition design](continuous-recognition-architecture.md).

## Assisted path and collection

`Scanner` / `recognition.ts` remain the local English OCR fallback. Text candidates go to `catalog.ts`, then explicit Review confirmation. Catalog requests have pacing, timeouts, expiry and strict URL validation.

`storage.ts` reconstructs imported app data field-by-field, validates aggregate limits, and persists version-1 JSON in localStorage. Existing backups remain compatible. A changed storage snapshot or another-tab event pauses writes to protect against stale overwrite; this is not a multi-user database or a cross-tab transaction protocol. JSON exports preserve collection/review/decks; CSV protects against spreadsheet formula injection.

## Limits

Spatial tracking cannot prove that an identical physical card is a different copy after leaving view. Binder pans/crossing cards can confuse assignment; use one stable layout and verify counts. Learned or classical visual evidence and synthetic replay tests are not calibrated recognition probabilities or held-out physical-card accuracy. The UI reports measured processing time and exact loaded reference count. Browser storage quotas, cache eviction and origin changes can lose local data, so export collections regularly.
